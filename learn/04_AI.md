## 5. ETL Là Gì?

### 5.1. Định Nghĩa

**ETL** là viết tắt của:

```text
Extract -> Transform -> Load
```

Ý nghĩa:

- Extract: lấy dữ liệu thô.
- Transform: làm sạch, chia nhỏ, chuyển đổi.
- Load: lưu dữ liệu đã xử lý vào database.

Trong Library74:

```text
PDF sách -> text -> chunks -> vectors -> database -> summary/tags/audience
```

### 5.2. Vì Sao Cần ETL PDF?

PDF là file dài. AI không thể tìm kiếm nhanh trực tiếp trên toàn bộ file mỗi lần user search.

Vì vậy hệ thống xử lý PDF trước:

1. Đọc text từ PDF.
2. Chia thành nhiều đoạn nhỏ.
3. Biến từng đoạn thành vector.
4. Lưu vector vào database.
5. Khi user search, chỉ cần so vector query với vector đã lưu.

Trả lời hội đồng:

```text
ETL giúp chuyển PDF từ dữ liệu thô thành dữ liệu có thể tìm kiếm bằng AI. Hệ thống xử lý sách trước một lần, lưu vector vào database, nên lúc người dùng search thì phản hồi nhanh hơn.
```

## 8. Chunking Là Gì?

### 8.1. Vấn Đề Thực Tế

Một cuốn sách có thể dài hàng trăm trang. Không thể biến cả cuốn sách thành một vector duy nhất vì:

- Mất chi tiết.
- Query nhỏ khó khớp đúng đoạn.
- Model có giới hạn độ dài.

Vì vậy ta chia sách thành các đoạn nhỏ gọi là **chunk**.

### 8.2. Chunk Trong Project

Project dùng sliding window theo ký tự:

```text
chunk_size = 1500
overlap = 150
```

Ý nghĩa:

- Mỗi chunk khoảng 1500 ký tự.
- Hai chunk kế tiếp chồng lên nhau 150 ký tự để không mất ngữ cảnh ở điểm cắt.

Ví dụ:

```text
Chunk 1: ký tự 0 -> 1500
Chunk 2: ký tự 1350 -> 2850
Chunk 3: ký tự 2700 -> 4200
```

Trả lời hội đồng:

```text
Chunking giúp chia sách dài thành nhiều đoạn nhỏ để model hiểu tốt hơn. Overlap giúp giữ ngữ cảnh ở ranh giới giữa hai đoạn, tránh mất ý khi câu bị cắt.
```

## 9. Embedding Là Gì?

### 9.1. Định Nghĩa Dễ Hiểu

**Embedding** là cách biến văn bản thành một dãy số để máy tính so sánh ý nghĩa.

Ví dụ:

```text
"lập trình backend" -> [0.12, -0.04, 0.88, ...]
"xây dựng API server" -> [0.10, -0.02, 0.83, ...]
```

Hai câu khác chữ nhưng gần nghĩa thì vector sẽ gần nhau.

### 9.2. Embedding Trong Project

Project dùng SBERT/Sentence Transformers để tạo vector 768 chiều.

File liên quan:

```text
LMS_AI/ai_etl/embedding_client.py
LMS_AI/api_service.py
```

Vector được lưu vào database bằng `pgvector`.

Trả lời hội đồng:

```text
Embedding giúp hệ thống so sánh ý nghĩa thay vì chỉ so khớp chữ. Nhờ vậy người dùng có thể tìm theo mô tả hoặc nhu cầu, không cần nhớ đúng tên sách.
```

## 10. pgvector Là Gì?

### 10.1. Vấn Đề Thực Tế

Sau khi tạo vector cho hàng nghìn đoạn văn, ta cần lưu và tìm vector gần nhất.

Database thường chỉ giỏi query số, chữ, ngày tháng. `pgvector` giúp PostgreSQL lưu và tìm vector.

### 10.2. Định Nghĩa

**pgvector** là extension của PostgreSQL để lưu vector và tìm kiếm similarity.

Ví dụ bảng vector:

```text
ai_engine.publication_vectors
```

Mỗi dòng thường có:

```text
publication_id
chunk_text
embedding vector(768)
```

Khi user search:

```text
query text -> query vector -> tìm chunk vector gần nhất -> gom về publication_id
```

Trả lời hội đồng:

```text
pgvector cho phép lưu embedding ngay trong PostgreSQL và query vector gần nhất. Nhờ vậy hệ thống không cần thêm một vector database riêng, giảm độ phức tạp triển khai.
```

Semantic search hiểu ý nghĩa gần đúng.

### 11.2. Luồng Semantic Search Trong Library74

```text

```

Input:


```text

Semantic search không trả trực tiếp toàn bộ sách. AI service trả danh sách ID sách phù hợp, backend sau đó lấy dữ liệu nghiệp vụ đầy đủ để đảm bảo quyền, trạng thái và format response thống nhất.
```

## 14. Fallback Là Gì?

### 14.1. Vấn Đề Thực Tế

LLM có thể lỗi:

- Quá tải.
- Timeout.
- Trả JSON sai format.
- Bị quota limit.

Nếu LLM lỗi mà cả pipeline fail, sách sẽ không được index.

### 14.2. Fallback Trong Project

Nếu Gemini fail, pipeline có thể dùng fallback deterministic:

- Vẫn lưu vector.
- Vẫn có metadata cơ bản.
- Hệ thống vẫn tìm kiếm được sách.

Trả lời hội đồng:

```text
Fallback giúp hệ thống bền hơn. Nếu Gemini tạm thời lỗi, AI pipeline vẫn có thể index vector để search, thay vì bỏ toàn bộ quá trình xử lý sách.
```

## 15. Hash Skip Và Idempotency

### 15.1. Vấn Đề Thực Tế

Nếu cùng một PDF bị xử lý lại nhiều lần, hệ thống sẽ:

- Tốn thời gian.
- Tốn quota.
- Tạo vector trùng.
- Gây nhiễu dữ liệu.

### 15.2. Hash File

Project tính hash của file PDF.

Nếu file không đổi:

```text
hash mới == hash đã lưu -> skip ETL
```

Nếu file đổi:

```text
hash mới khác hash cũ -> xóa vector/tag cũ -> re-index sạch
```

### 15.3. Idempotency Là Gì?

**Idempotency** nghĩa là chạy lại cùng một thao tác nhiều lần nhưng kết quả cuối vẫn nhất quán.

Trả lời hội đồng:

```text
AI ETL có idempotency bằng file hash. Nếu PDF không đổi thì bỏ qua xử lý lại, nếu PDF đổi thì re-index sạch. Cách này tiết kiệm tài nguyên và tránh dữ liệu trùng.
```

## 16. Celery Và RabbitMQ

### 16.1. Vì Sao Cần Queue?

Xử lý PDF có thể mất vài giây đến vài phút. Nếu backend chờ ngay trong request upload, người dùng sẽ phải chờ lâu.

Queue giúp xử lý nền.

```text
Backend gửi job -> RabbitMQ giữ job -> Celery worker lấy job -> xử lý PDF
```

### 16.2. RabbitMQ Là Gì?

RabbitMQ là message broker, giống hàng đợi công việc.

Ví dụ:

```text
book.processing.queue
```

### 16.3. Celery Worker Là Gì?

Celery worker là process Python chạy nền, lắng nghe queue và xử lý task.

File chính:

```text
LMS_AI/worker.py
```

Trả lời hội đồng:

```text
RabbitMQ lưu job xử lý sách, Celery worker xử lý job nền. Cách này giúp upload sách không bị kẹt vì AI xử lý lâu, đồng thời dễ retry nếu lỗi tạm thời.
```

## 19. ALS Là Gì?

### 19.1. Định Nghĩa Dễ Hiểu

**ALS** là thuật toán recommendation dùng ma trận user-item.

Nói đơn giản:

```text
Nếu user A và user B có hành vi giống nhau,
thì sách user A thích có thể được gợi ý cho user B.
```

Nó học từ dữ liệu tương tác:

```text
user_id, publication_id, action_type
```

### 19.2. Vì Sao Dùng ALS?

ALS phù hợp với implicit feedback, tức là hành vi không phải rating trực tiếp:

- Xem.
- Wishlist.
- Mượn.

Người dùng không cần chấm điểm tất cả sách, hệ thống vẫn học được từ hành vi.

Trả lời hội đồng:

```text
ALS phù hợp vì dữ liệu thư viện chủ yếu là implicit feedback như xem, wishlist và mượn sách. Thuật toán học quan hệ user-item để gợi ý sách có khả năng phù hợp.
```

## 31. Những Câu Hội Đồng Hay Hỏi

### Câu 1: AI trong hệ thống dùng để làm gì?

Trả lời:

```text
AI dùng để tìm kiếm ngữ nghĩa, gợi ý sách cá nhân hóa và xử lý PDF để tạo summary, audience, tags và vector. Nó giúp người dùng tìm sách theo nhu cầu chứ không chỉ theo keyword.
```

### Câu 2: Vì sao không để backend Java làm AI luôn?

Trả lời:

```text
AI dùng nhiều thư viện Python như sentence-transformers, PyMuPDF, Celery và các thư viện ML. Tách AI thành service riêng giúp backend Java tập trung nghiệp vụ, còn Python service tập trung model/vector, dễ mở rộng và deploy độc lập.
```

### Câu 3: Embedding là gì?

Trả lời:

```text
Embedding là vector số đại diện cho ý nghĩa của văn bản. Hai đoạn văn gần nghĩa sẽ có vector gần nhau. Nhờ embedding, hệ thống tìm sách theo ý nghĩa thay vì chỉ khớp từ khóa.
```

### Câu 4: Semantic search khác keyword search thế nào?

Trả lời:

```text
Keyword search tìm chữ trùng, còn semantic search tìm ý nghĩa gần nhau. Ví dụ người dùng tìm 'xây dựng API server', semantic search có thể tìm sách backend dù title không chứa đúng cụm đó.
```

### Câu 5: pgvector dùng để làm gì?

Trả lời:

```text
pgvector giúp PostgreSQL lưu embedding vector và tìm vector gần nhất bằng cosine distance. Nhờ vậy project không cần triển khai thêm vector database riêng.
```

### Câu 6: Vì sao phải chia PDF thành chunk?

Trả lời:

```text
PDF quá dài để xử lý một lần và một vector duy nhất sẽ mất chi tiết. Chia chunk giúp lưu ý nghĩa từng đoạn nhỏ, từ đó search chính xác hơn. Overlap giữ ngữ cảnh giữa các chunk.
```

### Câu 7: Vì sao dùng RabbitMQ/Celery cho PDF?

Trả lời:

```text
Xử lý PDF có thể lâu, nên không nên bắt người dùng chờ trong request. Backend đưa job vào RabbitMQ, Celery worker xử lý nền và callback khi xong.
```

### Câu 8: Gemini dùng ở đâu?

Trả lời:

```text
Gemini dùng trong bước tổng hợp metadata sau khi đọc PDF: tạo summary, audience và tags. Project không gọi Gemini cho mỗi lần search để tránh chậm và tốn quota.
```

### Câu 9: Recommendation dựa trên dữ liệu nào?

Trả lời:

```text
Recommendation dựa trên hành vi người dùng như xem sách, thêm wishlist và mượn sách. Các hành vi có trọng số khác nhau, sau đó thuật toán ALS học quan hệ user-item để gợi ý.
```

### Câu 10: Cold start là gì và xử lý thế nào?

Trả lời:

```text
Cold start là khi user mới chưa có dữ liệu hành vi. Project fallback bằng trending hoặc content-based recommendation để vẫn có gợi ý thay vì trả rỗng.
```

## 33. Bản Tóm Tắt Một Phút

Nếu phải giải thích AI Library74 trong một phút:

```text
AI trong Library74 là một service Python tách riêng khỏi backend Java. Nó có hai phần chính: FastAPI để phục vụ semantic search/recommendation realtime, và Celery worker để xử lý PDF nền qua RabbitMQ.

Khi sách có PDF, worker tải file, trích text bằng PyMuPDF, làm sạch, chia chunk, tạo embedding bằng SBERT và lưu vector vào PostgreSQL pgvector. Sau đó hệ thống chọn một số chunk đại diện và gọi Gemini một lần để tạo summary, audience và tags. Kết quả được lưu vào database và callback về backend.

Khi người dùng tìm kiếm, AI service biến câu query thành vector và tìm các chunk gần nhất để trả về publication_ids. Khi gợi ý sách, service dùng hành vi như xem, wishlist và mượn sách với ALS, có fallback trending/content-based cho user mới. Cách này giúp hệ thống tìm và gợi ý sách thông minh hơn nhưng vẫn giữ backend Java làm nơi quản lý nghiệp vụ và bảo mật.
```
